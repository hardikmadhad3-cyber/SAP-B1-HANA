SAP B1 Web App - Server Install and Start Guide
================================================

Quick one-click install on another Windows server
-------------------------------------------------
1. Extract SAP-B1-Server-Package.zip on the server.
2. Edit backend\.env if database, SAP, or PORT settings are different.
3. Double-click INSTALL_ONE_CLICK.bat.
4. Open the app on the server:
   http://localhost:5001
5. Open from another LAN computer:
   http://SERVER-IP:5001

The backend listens on 0.0.0.0, so LAN access by server IP is supported.
INSTALL_ONE_CLICK.bat also registers a Windows Task Scheduler task named:
SAP-B1 Backend Auto Start

If Task Scheduler is blocked by Windows permissions, it creates a Startup folder
shortcut with the same name instead.

That means you do not need to start the backend manually every time after this
Windows user logs in. If the machine reboots and no user logs in, the scheduled
task will not run until login.

Build package for another server
--------------------------------
Double-click:
BUILD_SERVER_PACKAGE.bat

This creates:
dist\SAP-B1-Server-Package.zip

By default backend\.env is not included in the zip. For a trusted internal
server package that includes backend\.env, run:
powershell -ExecutionPolicy Bypass -File .\deployment\build-server-package.ps1 -IncludeEnv

Manual PowerShell commands
--------------------------
Open PowerShell in the project folder:
cd "D:\Hetal\SAP-B1 (2)\SAP-B1\SAP-B1\SAP--B1\SAP-B1\SAP-B1"

Install and build:
powershell -ExecutionPolicy Bypass -File .\deployment\install-one-click.ps1

Start backend and register auto-start:
powershell -ExecutionPolicy Bypass -File .\deployment\start-backend-service.ps1 -InstallAutoStart

Stop backend:
powershell -ExecutionPolicy Bypass -File .\deployment\stop-backend-service.ps1

Stop backend and remove auto-start:
powershell -ExecutionPolicy Bypass -File .\deployment\stop-backend-service.ps1 -RemoveAutoStart

Backend only, manual dev start:
cd backend
npm.cmd install
npm.cmd start

Frontend only, manual dev start:
cd frontend
npm.cmd install
npm.cmd start

Production frontend build:
cd frontend
npm.cmd run build

Port already started / kill process guide
-----------------------------------------
Check process using backend port 5001:
Get-NetTCPConnection -LocalPort 5001 | Select-Object LocalAddress,LocalPort,State,OwningProcess

Kill process by PID:
Stop-Process -Id PID_NUMBER -Force

If Get-NetTCPConnection shows Access Denied, use this alternative:
netstat -ano | findstr :5001
taskkill /PID PID_NUMBER /F

For frontend dev port 3000 or 3001:
Get-NetTCPConnection -LocalPort 3000 | Select-Object LocalAddress,LocalPort,State,OwningProcess
Stop-Process -Id PID_NUMBER -Force

Get server IP for LAN
---------------------
ipconfig

Use the IPv4 Address of the active Ethernet or Wi-Fi adapter:
http://SERVER-IP:5001

LAN troubleshooting
-------------------
1. On the server, check backend health:
   http://localhost:5001/health

2. From another LAN computer, check:
   http://SERVER-IP:5001/health

3. If localhost works but LAN does not:
   - Confirm both computers are on the same network.
   - Confirm Windows Firewall allows inbound TCP port 5001.
   - Run INSTALL_ONE_CLICK.bat as Administrator to let it add the firewall rule.
   - Check that backend\.env PORT is 5001 or use that configured port in the URL.

4. Check backend logs:
   logs\backend-service.log

Common errors
-------------
"node is not recognized" or "npm is not recognized":
Install Node.js LTS, close PowerShell, open it again, and rerun the installer.

"Running scripts is disabled":
Use:
powershell -ExecutionPolicy Bypass -File .\deployment\install-one-click.ps1
For manual npm commands in PowerShell, use npm.cmd instead of npm.

"Port 5001 already in use":
The backend may already be running. Open http://localhost:5001/health.
If it is the wrong process, kill it with the port commands above.
